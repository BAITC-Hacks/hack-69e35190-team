Как это работает внутри
  1. Сообщение разбирается на поля: город, дата, тип мероприятия, категория, бюджет, опционально язык и длительность.
  2. Чего не хватает — спрашиваем по одному полю за раз (можно отвечать словом или кнопкой-подсказкой).
  3. Backend проверяет CSV: город и категория → дата, бюджет, формат, язык и длительность → порядок по цене «от» и id → до 3 карточек. AI-слой добавляет объяснение из проверенных полей и конкретного фрагмента описания.
  4. Три исхода различимы явно: подобрали / нет такой категории в городе / кандидаты есть, но никто не подходит — с разбивкой причин.
  5. Тот же запрос даёт тот же порядок. Можно уточнять на лету: «бюджет 500000», «давай на казахском» — backend пересчитает результат с учётом уже собранных полей.
Каталоги и загрузка CSV

Загрузка пополняет базу знаний, но не дообучает веса модели. Новый CSV должен содержать те же столбцы, что исходный каталог; списки разделяются символом |. Укажите полный период, на который известна занятость.

Если API настроен, фрагменты описаний передаются OpenAI для индексации; сложные сообщения — для разбора запроса. Ключи остаются на сервере.

Проверьте подбор на примерах

Три сценария: ранжирование в плотной категории, редкая категория и запрос без результата. Каждый пример отправляет запрос в выбранный каталог.

Повтор сравнит порядок карточек с предыдущим результатом. Время каждого ответа показано под результатом; ориентир — до 10 секунд.
