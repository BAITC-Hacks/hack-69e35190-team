# Подбор подрядчиков

Python-сервис и чат: до трёх подрядчиков с конкретными объяснениями из CSV. Занятость, город, категория, формат, бюджет, язык и длительность проверяются **кодом**, не моделью. Бронирования нет.

## Запуск

Python 3.9+, без установки сторонних библиотек:

```sh
python3 -m backend.api
```

Откройте <http://127.0.0.1:8000>. Не открывайте HTML через file:// или другой статический сервер: интерфейсу нужен Python API на том же адресе. После изменения Python-кода или .env перезапустите сервер. Если порт занят, остановите прежний процесс или используйте --port 8001 и соответствующий адрес.

Без API-ключа работают все фильтры, три статуса, локальный разбор сообщения и объяснения. Для AI заполните локальный .env по .env.example (не отправляйте ключи в чат/Git):

```dotenv
OPENAI_API_KEY=ваш_ключ
AI_EMBEDDING_MODEL=text-embedding-3-small
AI_EMBEDDING_DIMENSIONS=256
AI_CHAT_MODEL=gpt-4.1-mini-2025-04-14
```

Сервер строит недостающие индексы в фоне. При ошибке API подбор остаётся доступен; статус и кнопка повтора — в «Каталоги и загрузка CSV». NVIDIA сейчас не используется: для этого решения достаточно одного провайдера.

## Что значит «учится на CSV»

Это пополнение базы знаний, **не дообучение весов модели** (оно исключено заданием для 66 записей):

```text
CSV → проверка схемы/календаря → отдельная версия каталога
    → фрагменты description → эмбеддинги → сохранённый поисковый индекс

Сообщение → правила / LLM-извлечение полей → проверка полей кодом
    → строгие фильтры → сортировка (цена «от», id) → максимум 3
    → поиск фрагмента внутри каждого профиля → проверяемое объяснение
```

Новые данные реально используются в подборе и объяснениях. Словари городов, категорий, языков и форматов дополняются из выбранного CSV. Каталоги изолированы, профили с одинаковыми id в разных каталогах не смешиваются. Модель не придумывает новых подрядчиков.

### Загрузка нового кейса

В интерфейсе откройте «Каталоги и загрузка CSV»: название, CSV, **полный известный период календаря**, затем «Загрузить CSV». Каталог автоматически выбирается; диалог сбрасывается. Период нельзя выводить из минимальной/максимальной занятой даты: на краях могут быть свободные дни.

Формат: UTF-8 CSV (BOM допустим), разделитель столбцов запятая, списки через |, даты YYYY-MM-DD, флаги true/false без учёта регистра. Поля:

```text
id,anon_name,categories,city,price_from_kzt,event_formats,languages,max_hours,busy_dates,description,synthetic,city_imputed,price_imputed
```

Пустой max_hours или null означает услугу без ограничения присутствия; пустой busy_dates допустим **в пределах заявленного периода**. Для самостоятельно выдуманных профилей обязательно synthetic=true. Пустые описания/имена, дубли id, неправильные числа/даты/флаги отклоняются. Максимум 2 МБ, 5000 профилей в каталоге и 50 каталогов в локальном демо.

Новые CSV с **иной схемой или другой предметной областью** требуют адаптера; автоматического понимания произвольных таблиц нет. При изменении содержимого или периода создаётся новая версия; старые не перезаписываются. Повторная загрузка идентичного CSV с тем же периодом идемпотентна. Оригинальный датасет не меняется. Загруженные CSV, метаданные и индексы сохраняются в .local/datasets/; исходный индекс — в .cache/. Обе папки игнорируются Git.

С настроенным ключом описания передаются OpenAI для эмбеддингов; для сложных запросов передаются сообщение, текущие поля и словарь каталога. Ключи никогда не передаются во frontend. Не загружайте конфиденциальные данные без разрешения на такую обработку.

## Проверить вживую

Кнопки над чатом запускают плотную категорию, две разные даты, редкую категорию и оба варианта пустого ответа. Регрессия со скриншота:

> фотосессия на корпоратив, в Алмате на 25 октября, в 15:00 на 3 часа, бюджет 50тыс, язык не важен

Распознаются фотограф, Алматы, корпоратив, 25.10.2026, 3 часа и 50 000 ₸. Ожидается no_matches: кандидатов 8, все превышают бюджет, 3 заняты, 4 не берут формат (причины пересекаются). Время 15:00 не проверяется — календарь подневный; интерфейс сообщает об этом.

```sh
python3 -m unittest discover -s tests -v
python3 -m ai_layer prepare-index
python3 -m ai_layer demo
```

Тесты без сетевых вызовов проверяют исходные шесть сценариев, диалог, импорт/изоляцию/перезапуск, ошибочные CSV, отказ провайдера и HTTP 500. ai_layer demo отдельно показывает объяснения заранее выбранных карточек; это не замена живому API.

## API

```sh
curl -X POST http://127.0.0.1:8000/recommendations \
  -H 'Content-Type: application/json' \
  -d '{"city":"Алматы","event_date":"2026-10-10","event_type":"корпоратив","category":"Ведущий","budget_kzt":1500000}'
```

POST /recommendations: поля выше, опционально language, duration_hours, dataset_id (по умолчанию default). Три бизнес-статуса с HTTP 200: matched, category_not_in_city, no_matches. Неправильный ввод — HTTP 400, внутренняя ошибка — JSON HTTP 500 с безопасным request_id.

POST /chat: {message, slots?, dataset_id?}. Возвращает нормализованные slots, missing_field, prompt, choices, warnings, parser, result (или null, если нужны уточнения). Для продолжения передавайте полученные slots; при смене каталога сбрасывайте их. Поля в ответе видны пользователю и могут быть исправлены следующим сообщением.

GET /datasets: версии, словари, период, число профилей, хеш и статус индекса (lexical/indexing/ready/degraded). POST /datasets: {name, csv, calendar_start, calendar_end}. POST /datasets/index: {dataset_id} — фоновый повтор индексации. GET /health: состояние и размер исходного каталога.

## Ограничения и документы

Это локальное хакатон-демо, не публичный production-сервис: не выставляйте порт в интернет без аутентификации, квот, TLS и полноценного HTTP-сервера. Стоимость «от» не является окончательным предложением, а свободная дата не гарантирует бронирование. При отказе API включаются локальные правила; они не понимают любой возможный свободный текст и могут попросить уточнение.
