# Подбор подрядчиков — AI-слой объяснений

В репозитории лежат исходный CSV на 66 профилей, [контракт сервиса](docs/spec.md), [схема AI-пайплайна](docs/ai-pipeline.md) и [демо-сценарии](docs/demo-queries.md). Реализован отдельный модуль `ai_layer/`: он получает от backend уже отфильтрованные и отсортированные карточки, выбирает точный фрагмент `description` и добавляет к каждой карточке `explanation`. HTTP API и интерфейс разрабатываются отдельно.

## Локальная проверка без ключа

Нужен Python 3.9+; внешних библиотек нет.

```sh
python3 -m unittest discover -s tests -v
python3 -m ai_layer demo
python3 -m ai_layer demo --case dense_autumn_oct10
```

Демо берёт **готовые id карточек** из `examples/demo-cases.json` и показывает только работу AI-слоя; оно не подменяет проверку фильтров backend. Без ключа фрагмент описания выбирается локальным детерминированным поиском.

## Подключение OpenAI Embeddings

Заполните `OPENAI_API_KEY` в локальном [`.env`](.env); файл игнорируется Git. Ключ не нужно отправлять в чат и нельзя помещать во frontend. `NVIDIA_API_KEY` оставлен для будущих экспериментов и текущим кодом не используется.

```sh
python3 -m ai_layer prepare-index
python3 -m ai_layer demo
```

Первый вызов один раз индексирует фрагменты `description` через `text-embedding-3-small`. Векторы хранятся в игнорируемой Git директории `.cache/`; ключ в индекс не записывается. При запросе используется один эмбеддинг поисковой фразы. Если ключа, индекса или сети нет, модуль автоматически выбирает фрагмент локально. Исходные данные и модель не дообучаются.

## Точка интеграции с backend

```python
from ai_layer import AIExplainer

explainer = AIExplainer()  # создать один раз при запуске backend
result = explainer.enrich_response(order, response)
```

`order` — словарь входного запроса, `response` — словарь ответа по [spec.md](docs/spec.md) с уже выбранными `cards`. Метод возвращает копию: порядок и поля карточек сохраняются, добавляется только `explanation`. Для пустой выдачи внешние вызовы не выполняются. Перед объяснением модуль дополнительно сверяет карточку с CSV по городу, категории, дате, бюджету, формату, языку и длительности и откажется объяснять неподходящего подрядчика.

Ключ API нужен только на сервере для семантического поиска. Текущий модуль не вызывает LLM для свободной генерации: проверяемое объяснение строится шаблоном из полей CSV и выбранного дословного фрагмента описания.
